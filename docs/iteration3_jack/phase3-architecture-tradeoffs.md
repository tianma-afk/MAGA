# P3T3 架构权衡与决策依据

日期：2026-11-16。候选保持P3T2冻结版本；本轮完成统一对照，不作最终ADR、不Merge。证据来自[结果](phase3-evaluation-results.md)、[逐query审计](phase3-case-audit.md)、[冻结协议](phase3-evaluation-protocol.md)，复现见[说明](phase3-reproduction.md)。

## Observation：本轮观察

开发KC8 Baseline/A/B/C=50.00%/31.82%/63.64%/50.00%；保留=33.33%/16.67%/50.00%/16.67%。B开发提升2例、0例KC下降；保留提升1、下降1、持平1。A开发2升3降，保留0升1降；C开发全持平，保留1降。

P8下界排序与KC不一致：保留A16.67%最高，但只覆盖N13的恢复，遗漏同例检测，KC仅16.67%。B保留P8下界8.33%与基线相同，却在N14补一个容量方向知识点；多拿同一知识的页不等于覆盖更多必要知识。

所有方案0伪造页/0重复ID/0超8/0本轮主批错误；所有返回均8页。C降低文本相似代理而没有改善本集已标覆盖；Top32 oracle覆盖保留100%，最终16.67%，显示当前选择规则留下明显差距，不证明拓宽候选本身无价值。

## Interpretation：机制、质量属性与风险

|质量属性|A：词法扩展/单次排序|B：规划/基点检索/合并|C：宽候选/覆盖/去冗余|
|---|---|---|---|
|Functional Suitability|在N03检测有收益，N05/N07/N08等已标来源退化；有限规则无法保证知识覆盖|本轮覆盖最有希望，但N01概念识别后仍无词法落点，N13多意图仍丢检测|池内有知识仍未选出；词项覆盖不等于任务必要知识覆盖|
|Performance Efficiency|本轮最快；字段饱和与较少章节读取可解释，未做单因素耗时消融|串行规划加多次词法扫描；实际本地合并检索耗时高于规划，不能把所有额外延迟归因网络|逐候选整章读取/特征构造使开销明显，不能只看纯排序计算复杂度|
|Reliability|无新增上游依赖；规则误召回属质量失败，非HTTP错误|故障可精确回退，但超时会先等约15秒再本地检索/校验；回退不保证最终生成可用|无上游依赖；显式重排不可用钩子经Mock覆盖，代码错误仍可见，不静默伪成功|
|Maintainability|专属策略70行，映射与通用词需维护；少代码不证明规则可靠|专属152行，加严格计划/网络预算/目录/合并/诊断，责任清晰但状态与外部契约更多|专属96行，特征/权重/阈值可解释但需验证；共享仓储读取方式成为成本敏感点|
|Testability|完全离线、确定性，容易反例回归|故障可Mock；Mock不能检验语义；实际模型别名和fresh计划不能精确重现|固定候选池可重现选择，实际相关性仍需人审；相似文本互补风险不能仅靠单测消除|
|Operability|无需额外配置，公共搜索/前端不动|复用原配置但增加独立规划可用性要求、计费与日志预算运维|无需额外配置，但候选规模与I/O需监测|
|Cost|无规划API费，CPU/磁盘成本未折现|17次真实规划含预检，11573总Token，费用unknown；最终生成未计|无规划API费，本地运行成本高于本轮Baseline/A，未折现|

模块数/行数仅描述变更规模，不是复杂度或可维护性分数。三者仍为实践适配→专属策略→公共检索/仓储，无数据库、Embedding、新依赖、公开API或最终生成改动。约束促使策略在实践链路隔离，避免将实验规则扩散到问答、自测、跨章搜索。

本轮没有吞吐、峰值内存、真实故障率或最终教学效果指标；不把未测质量属性填成优秀/零成本。A/C零规划费也不表示整个产品无模型费用。

## Recommendation：当前最支持的分层判断

1. **B是最值得优先补充验证的候选**：本轮开发与保留KC均最高，改善跨过N02可用性、N09传播约束及N14容量方向，而非单一成功页。但保留收益只有1升1降，平均延迟约Baseline的2.4–2.6倍，且关键新增8:20仅为概览。证据不足以直接批准替换。
2. **Baseline继续作为生产保守默认与对照**：避免在有限标签下以局部收益换取未接受的延迟/成本。当前存在明确产品不足，保留它不是宣称问题已解决。
3. **A可作低延迟候选，但不宜凭速度或P8下界直接采用**：它在本集KC退化，且重复相近知识页可能挤占多知识需求；同时A的5:7/13等有用战术页未被标签充分评价，须同口径人审后再判实际退化程度。
4. **当前C不支持优先集成**：开发已标质量与基线相同、保留较低，同时更慢。这个限定版本在本轮主要指标上缺少收益，不代表所有重排方法无效。候选oracle差距值得解释，但本轮不改权重追分。

这是质量属性权衡建议，不是“B获胜”或最终架构决策。四方案存在成本/覆盖冲突；不以一个加权总分掩盖人工可接受代价，也不按小数位或3例保留结果宣称显著优越。

## Uncertainty与最小补充验证

- 先人工审核少量决策敏感来源：N01/N02的5:7/13、N13的6:19与恢复页、N14的8:20/16、A退化例新增页。当前未审比例很高；修改标签应升版并对四个冻结结果一并重算，保留本轮原始v4结果。
- 人工明确愿意为来源覆盖增加多少秒延迟与模型费用。若B仍有优势，再用少量新独立查询确认（特别是N13同类多意图遗漏、N01自然表达、N15外部依赖替换）；额外真实调用需要新的明确批次预算，本轮没有追加。
- 只有评审接受以上代价并作最终选择后才进入P3T4；真实最终生成/来源充分性与浏览器停止后生命周期另验，不从结构测试通过推导学习效果。

组合策略目前只有机制上的可能性。A在N03有效、B在N02/N14有效，可能互补，也可能叠加漂移；C现版本无已测净收益，A+C没有充分证据支持默认探索。若人工决定研究组合，需作为新候选、新版本及新验证集合，不在本轮偷偷实现第四种方案。
