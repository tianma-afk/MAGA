### C1：模块化单体与浏览器本地持久化

- **决策、轮次与类型：** 轮前 `7410636` 已明确记录 ADR-001；前两轮沿用并扩展。事实：React 客户端通过 JSON/HTTP 调用 FastAPI，后端按课件、教学、模型与业务模块组织；学习数据在浏览器，后端没有学习记录数据库（E01、E08–E10）。
- **背景和备选：** E01 明确以个人电脑/演示机、小规模为背景，对比微服务及消息队列、服务发现等额外设施，理由是减少部署复杂度和网络故障点。没有数据库方案或前端状态库的系统比较。
- **架构知识及属性：** 客户端—服务器、模块化单体、职责划分、持久化边界；影响可部署性、可修改性、可靠性和隐私。
- **实现与代价：** `main.py:create_app` 统一装配，`ChapterStore` 管理源文件；`state.ts`、`quiz.ts`、`progress.ts`、`design.ts` 按职责存储。收益是低运维负担；已记录代价是无账号、无跨设备同步、清站点数据丢记录。不能称严格分层架构：业务模块直接依赖 `httpx`，检索也依赖具体 Store。
- **验证：** E11 中章节隔离、存储损坏/拒绝、恢复测试支持边界行为；无微服务对照、存储性能或多人扩展实验。
- **答辩可用性：** 可直接形成基础选型案例，但必须标注轮前继承，不能声称是前三轮重新选型或性能最优。

### C2：外部模型边界与结构化可信输出契约

- **选择依据：** 文档要求真实模型教学、来源可追溯、无配置明确 503；这不是为最大化 AI 可用率选择的降级方案。
- **架构知识及属性：** 信任边界、数据契约、输入/输出验证、错误隔离、配置分离；影响安全性、可靠性、可修改性和可用性。

### C3：轻量 RAG 从章节检索演进到共享中英术语模块

- **变化、轮次与类型：** 轮前 ADR-002 明确选择有限文本检索而非向量库。第一轮 `486cc26` 新增跨章 `search_all`；第二轮 `49c66fa` 把原本分离的搜索/导师分词统一为 `retrieval_terms.py`，补 OCR、英文边界、词形与中文噪声过滤。前者为明确决策，后者有 diff 和问题记录。
- **背景、备选与理由：** 小规模章节材料不需要先引入 embedding/向量库；原检索中英表达不一致、子串与虚词产生噪声（E01、E04 T10、E05）。语义/混合检索和重排作为未来方向被提及，但没有实际对照试验，不能称其输给当前方案。
- **架构知识及属性：** 检索增强生成、共享策略模块、关注点分离、渐进演进、基于指标验证；影响可修改性、可测试性、检索有效性与资源成本。
- **实现：** `ChapterStore` 解析 PPT；`query_terms/term_matches` 提供共享词处理；全局搜索标题权重 3，正文/备注/OCR 权重 1；`relevant_slides` 仍独立评分、最多 4 页。问答加入当前页与下一页，自测/实践各限制最多 8 个来源。没有向量索引、embedding 或 PDF 全书索引。共享词处理不等于统一了全部排序算法。
- **验证：** E12 固定 10 概念、20 中英查询，比较 `44a1e3f` 旧搜索与当前实现；E04/E05 记录核心页 Top-5 命中 **10/20 → 18/20**，security/安全性未命中仍保留；`test_search.py`、`test_retrieval_noise.py` 覆盖词边界、去重、OCR 和噪声。
- **证据限制：** 本次未复算，原结果 JSON 不在仓库；脚本固定旧搜索实现，却使用当前 `ChapterStore` 与当前本地素材，不能称完整旧系统端到端复现。结果仅代表全局搜索小样本，不证明问答准确率、教学效果或通用语义检索性能；早期“目标章节命中”14/20→20/20 与指定核心页指标不可混用。
- **取舍：** 已记录轻量方案降低设施复杂度；推断其代价是词表维护与未知同义表达的覆盖局限。没有延迟、成本或大规模数据实验支撑进一步量化。
- **答辩可用性：** 本次最强演进案例，可演示“心跳/heartbeat”、子串噪声与指定页排序，明确指标分母和失败例。

### C4：图片型课件的离线 OCR 管道与运行依赖隔离

- **变化、轮次与类型：** 第二轮 `2ad91b9`（11/7 11:46:34）新增 OCR；提交说明明确写出“可选本地管道、运行期只读缓存、不导入 OCR 包”，属于有记录的技术选择。
- **问题、备选与依据：** E03/E07 记载 340 页中 82 页正文/备注不足，只有原图时模型无法读其文字；原方案只能提示资料不足。视觉模型作为后续方向被提到，但未见在线 OCR、离线 OCR、视觉模型的实际比较，无法确认当时逐一评估过。
- **架构知识及属性：** 离线预处理、文件接口、依赖隔离、内容适配与诚实降级；影响可部署性、可靠性、可修改性与内容覆盖。
- **实现：** `scripts/render-slides.ps1` 经 PowerPoint 生成 PNG；`scripts/ocr-slides.py` 生成 `data/ocr/{chapter}/{page}.txt`；`requirements-ocr.txt` 单独声明依赖；`ChapterStore.ocr` 读取，`Slide.ocrText` 接入问答、自测与搜索。当前 `excerpt` 顺序为正文、备注、OCR。`3063785` 等修复使损坏 OCR/课件可降级。
- **收益与代价：** 事实：服务端运行无需 OCR 包，可在缺缓存时保留阅读。推断：在线请求避免承担 OCR 推理开销；没有延迟对照证明。代价是素材生成依赖 Windows/PowerPoint、缓存需交接与重建、OCR 有误且无法识别箭头关系。
- **验证：** `test_ocr.py` 覆盖读取、API/搜索接入、缺失、非 UTF-8、上下文顺序；历史文档报告 9 页均值置信度 0.988、单页 1.5–6.3 秒及 Checksum 页示例。置信度不是人工识别准确率，原始逐页输出缺失，本次没有图片/OCR 缓存可复验。
- **答辩可用性：** 架构边界可信，效果数字需标注为历史自述。准备一页原图—OCR—模型上下文对照即可形成具体案例。

### C5：从组件临时状态到可恢复任务及结果版本依赖

- **变化、轮次与类型：** 第二轮 `49c66fa` 新增 `quizWorkspace.ts`、`useQuizWorkspace.ts`、`designValidity.ts`，调整 `QuizPane` 和 `DesignStudio`。E04 明确目标为学习/实践连续完成不丢输入成果；设计和演进证据较强，但详细替代方案评审缺失。

- **备选与依据：** Git 可比较旧组件状态/无结果签名与新模型；这是前后方案，不代表当时做过多方案评审。未见选择 localStorage 而非 IndexedDB/后端数据库的专项对比，不能补写成历史动机。
- **架构知识及属性：** 状态所有权与生命周期解耦、持久化模型分离、派生结果失效、兼容演进、故障下的数据保护；影响可靠性、可用性、可测试性、可修改性。
- **实现：** 练习草稿、结果选择和滚动位置独立于历史存储；草稿 ID 复用为提交 ID并对账，页码绑定来源；坏字段独立降级，`pagehide`/卸载补存并防止清空后复活。实践用输入的确定性 JSON 签名判断 `current/stale/unrecorded/missing`，上游失效传递下游；旧数据可读，失败/取消/保存失败保留已有成果。
- **协作边界：** 本地对账和写入保护不等于数据库事务或跨标签强一致协议；输入签名不包含模型版本、提示词版本、课件/OCR 版本，不能保证这些外部因素变化后仍识别旧结果。

## 8. 主要缺口与风险

1. **时间与责任归属丢失。** OCR 日期冲突、第二轮大提交包含多阶段成果，靠 Git 无法还原全部决策先后；作者与 AI 协作标记不能证明是谁实际提出/批准方案。第三轮若只留最终代码，以后更难还原真实动机。
2. **备选及放弃理由不足。** 现有 ADR 给出方向性理由，缺明确评价标准、约束变化和同一问题的候选比较。不能把本次识别的收益代价倒填成过去真实讨论。
3. **原始验证证据不随仓库交接。** E04/E05 引用的外部报告、JSON、图片和真实模型样本缺失；`.gitignore` 合理排除生成资产，但未另存脱敏清单与摘要。本次不能认证历史测试数字。
4. **指标含义易被夸大。** Top-5 核心页命中不是回答正确率，OCR 置信度不是人工准确率，单次模型耗时不是 P95，测试数量不是 Bug 数，CI 定义不是运行通过证明。
5. **静态描述滞后。** 早期架构图尚未完整覆盖实践与新状态模型；“模型网关”不能误画成统一抽象；后续 `ContentSource/SearchProvider/StorageBackend` 等建议接口不是当前实现。
6. **运行与数据风险尚未量化。** 本地数据丢失、外部模型依赖、无账号限流、提示注入与答案事实性、全量扫描和进程锁范围均可分析，但缺容量、安全和端到端效果实验。浏览器取消只确认本地不采纳迟到结果，不能证明后端及供应商一定终止任务。
7. **版本追溯范围有限。** 实践签名能检查用户输入依赖，未记录模型、提示词和课件版本；课件解析缓存看时间/大小，大纲签名看提取文本，不能等同于所有图片编辑都被检测。以上为代码分析发现的风险，不声称已有真实事故。

## 10. 最终结论

**今天可以直接用于初稿的材料：** 轮前四条 ADR 与质量属性场景、模块化单体和本地部署边界、当前 API/数据模型与模块职责、第一轮自测/搜索扩展的 Git 证据、第二轮 OCR/实践/状态/检索演进的 diff、故障修复记录、测试源码、固定检索评测集与复算脚本、最新交接及贡献台账。可以据此完成总体设计、逻辑/开发视图、主要场景数据流，以及带来源的 5 个重点案例分析。

**仍缺的关键证据：** 真实备选方案与当时取舍的确认记录、仓库外评估与验收原件、模型/素材/运行环境版本、实际性能/成本/安全效果数据、部署实例信息，以及第三轮截至结束时的实际变更与交接。第三轮未结束且本地没有可确认业务提交，不能填写其完成成果。

结论是“**材料部分充分，足以开始写，尚不足以无保留定稿**”。应保留现有轻量架构，用真实记录和有边界的复验补齐证据；不能以事后解释、AI 教学输出或理论上可分析的问题替代开发过程事实。
