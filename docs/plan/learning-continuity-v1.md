## 已完成契约

### 练习工作区

Key：`chapter-tutor:quiz-workspace:v1:{chapterId}`

```ts
interface QuizDraft {
  id: string;
  sourceSlide: number;       // 题目来源页，不随浏览位置变化
  sourceRecordId?: string;   // 重练时的原记录
  kind: 'generated' | 'retry';
  questions: QuizQuestion[];
  answers: number[];         // -1 表示未作答
  createdAt: string;
}
interface QuizWorkspace {
  version: 1;
  draft?: QuizDraft;
  activeRecordId?: string;
  scrollTop: number;
  updatedAt: string;
}
```

规则：

- 历史存储 `chapter-tutor:quiz:v1:{chapterId}` 结构不变。
- 草稿与历史分离；加载时逐字段校验，坏草稿只清空自身。
- 提交时草稿 `id` 即记录 `id`；若历史已存在同 id，加载时自动清除草稿并保留结果，避免重复。
- 后端生成仍为 3–5 题；本地重练 1–5 题；草稿允许 `-1`，提交要求全部作答。
- 切标签、关抽屉、翻页、切章、刷新均保留草稿；有草稿时替换需确认。
- 章节重置同时清理历史、草稿和进度。

### 主要文件

- `web/src/quizWorkspace.ts`：类型、校验、存取、草稿构造与提交
- `web/src/useQuizWorkspace.ts`：草稿生命周期、请求取消、存储失败、滚动位置
- `web/src/QuizPane.tsx`：展示与交互
- `web/src/quiz.ts`：导出 `isQuizQuestion` 供工作区复用
- `web/src/Tutor.tsx`：重置清理工作区

### 实践草稿

- 继续使用 `chapter-tutor:design:v1:current`，结构不变。
- 标题、场景、约束的每次输入都通过同一 `commit()` 边界写入完整项目，并更新 `updatedAt`。
- 页面显示“已保存到本地 HH:MM”；写入失败显示提示但不阻塞编辑。
- `reset()` 同步清理内存引用，避免清空后又被写回。
- 生成成功后只替换对应阶段结果，输入以当前草稿为准。

### 实践结果版本

- `designValidity.ts` 用确定性 JSON 计算 `analysisKey`、`tacticsKey`、`reviewKey`，比较输入与实际发送的字段（trim 后）。
- `DesignProject.versions` 为可选字段，记录各阶段生成时的签名；旧草稿缺省时状态为“未记录”，仍可查看和导出。
- 状态取值：`current`、`stale`、`unrecorded`、`missing`；上游过期会向下游级联。
- 过期分析禁止生成战术，过期战术禁止生成评审；按钮同时给出原因。
- 导出 Markdown 在对应章节写入同一提示，过期评审不会以“当前有效”出现。

### 安全错误映射

- `api.ts` 只按“状态码＋精确业务文案”白名单转换：资料不足、页码越界、搜索为空、实践无依据。
- 未识别的 422 字符串/数组、502、其他 503、HTML 错误页与畸形响应使用本地通用提示，不回显 detail、input 或上游正文。
- 只有 `503 + AI_NOT_CONFIGURED` 产生 `ConfigurationError`，并使用本地固定配置说明。
- 网络失败提示检查后端；AbortError 原样抛出。
- 实践新增 `onMode` 回调，三个阶段成功上报 `ai`、配置失败上报 `unconfigured`；自测成功也上报 `ai`。
