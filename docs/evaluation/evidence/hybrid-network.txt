## Resolution (2026-11-26 23:30, Asia/Shanghai)

The machine already had a Windows system proxy configured but the automation
shell did not inherit it:

    ProxyEnable : 1
    ProxyServer : 127.0.0.1:7890

With that proxy, the Jina host is reachable:

    $ curl -x http://127.0.0.1:7890 -H "Authorization: Bearer ***" \
        https://r.jina.ai/https://www.example.com
    code=200 time=0.677

    $ curl -x http://127.0.0.1:7890 -o /dev/null -w "%{http_code}" \
        https://api.jina.ai/v1/embeddings
    401        # reachable; 401 is the expected unauthenticated response

Real index build through the proxy:

    $ HTTPS_PROXY=http://127.0.0.1:7890 python -m server.retrieval_index
    {'total': 340, 'updated': 340, 'deleted': 0}

So the earlier failure was not a Jina outage and not a bad key; the shell was
bypassing the system proxy (direct connection), and campus DNS returns
intercepted addresses for Jina. Hybrid evaluation below uses this proxy.
